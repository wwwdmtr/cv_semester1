# Оценка техники приседаний по видео

Учебный проект по компьютерному зрению: исследование оценки двух ошибок приседания по позе человека и подготовка статьи.

**Текущий этап:** поиск моделей на готовых позах завершён; собран development-путь от RGB-видео до оценки автоматически найденных повторов. Следующая проверка — собственные размеченные видео команды.

Начните с [передачи контекста в едином дневнике](experiments/README.md#handoff-current): там замысел пользователя, причины решений, завершённые гипотезы и следующий шаг. Инструкции для агента — [AGENTS.md](AGENTS.md).

## Текущая модель и вход

Основная модель — логистическая регрессия на 35 геометрических признаках. Три класса: корректно по выбранным критериям, колени внутрь, малая глубина. Модель оценивает одно заранее выделенное полное повторение MediaPipe **world**-поз формы `(кадры,33,4)`; RGB-видео и нормированные экранные координаты непосредственно на вход не подаются. Score не является откалиброванной вероятностью правильности, отказы ещё не настроены.

Веса: `models/rehab26_baseline/squat_geometry.joblib`. Это модель на всех обучающих людях; опубликованные метрики относятся к внешним разбиениям, а не к независимому тесту этих весов. Временная CNN исследована, но основной вариант не заменяет.

## Применение без обучения

Python 3.10/3.11, команды из корня репозитория:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python scripts/predict_rehab26.py path/to/repetition.npy
```

Основной доверенный файл весов сейчас находится в репозитории по пути `models/rehab26_baseline/squat_geometry.joblib`; `data/raw/` и `.venv/` в Git не входят. Геометрический классификатор работает без PyTorch. Joblib-файлы нельзя загружать из недоверенных источников.

## Первый путь от RGB-видео

Эта версия обрабатывает один development-ролик, сохраняет MediaPipe world-позы и поддерживает ручные границы одного приседания либо автоматическое выделение всех завершённых повторов. Поток камеры сюда пока не входит.

1. Установите отдельные видеозависимости:

```bash
python -m pip install -r requirements-video.txt
```

2. С официальной страницы [Pose Landmarker](https://ai.google.dev/edge/mediapipe/solutions/vision/pose_landmarker/index#models) скачайте модель **Full** и сохраните её как `models/mediapipe/pose_landmarker_full.task`. Файл исключён из Git; путь можно изменить через `--pose-model`.

3. Положите короткий ролик в `data/raw/own_squats/dev/`. В кадре должен быть один человек целиком, включая стопы, и устойчивая стойка до и после движения. Сначала извлеките позы всего видео:

```bash
python scripts/predict_rehab26_video.py data/raw/own_squats/dev/P01_dev.mp4
```

Команда сохранит `world_poses_raw.npy` и `metadata.json` в `data/processed/own_squats/P01_dev/`. Пропущенные MediaPipe кадры остаются `NaN`, а не удаляются.

4. Повторите запуск с вручную выбранными границами одного полного повтора. Можно использовать включительные номера кадров:

```bash
python scripts/predict_rehab26_video.py data/raw/own_squats/dev/P01_dev.mp4 --start-frame 45 --end-frame 112
```

Или время в секундах, где правая граница не включается:

```bash
python scripts/predict_rehab26_video.py data/raw/own_squats/dev/P01_dev.mp4 --start-sec 1.5 --end-sec 3.8
```

Для предсказания используется доверенный файл `models/rehab26_baseline/squat_geometry.joblib`. Короткие внутренние пропуски позы интерполируются и записываются в метаданные; длинный пропуск, потеря позы на границе или покрытие ниже 90% дают технический отказ. Результат development-ролика не является независимой оценкой качества модели.

### Автоматическая оценка повторов

Одна команда извлекает позы, находит первую устойчивую стойку, выделяет завершённые приседания и применяет классификатор к каждому из них:

```bash
python scripts/predict_rehab26_video.py data/raw/own_squats/dev/P01_dev.mp4 --automatic-repetitions
```

В каталоге результата сохраняются `repetition_001_world_poses.npy`, `repetition_001_result.json` и такие же пары для следующих повторов. Общий `metadata.json` содержит границы, нижние точки, отклонённые незаконченные движения и сводку предсказаний. Если ролик начинается во время движения, поиск пропускает согнутую позу и калибруется по первой найденной устойчивой стойке с почти прямыми коленями.

Нельзя одновременно использовать `--automatic-repetitions` и ручные границы. Правильная глубина не является условием выделения движения: иначе целевой класс недостаточной глубины был бы удалён до классификации.

### Отдельная проверка автоматических границ

После извлечения поз всего ролика можно отдельно запустить прозрачный автомат временной сегментации:

```bash
python scripts/detect_rehab26_repetitions.py data/processed/own_squats/P01_dev/world_poses_raw.npy --fps 30
```

Он калибруется по начальной стойке, отслеживает сгибание коленей и уменьшение нормированного расстояния таз–голеностопы, после чего возвращает начало, нижнюю точку и конец каждого движения. В отличие от полного автоматического режима выше, эта диагностическая команда по умолчанию требует устойчивую стойку в начале массива поз. Результат сохраняется в `automatic_repetitions.json`.

Текущие пороги — исходная проверяемая версия, а не подтверждённые параметры приложения. До подключения к классификатору их нужно сравнить с ручными границами на development-роликах: посчитать пропуски, ложные и двойные срабатывания и ошибку границ в кадрах.

## Воспроизведение и проверки

Повторять обучение для чтения репозитория или продолжения видеопути не требуется. При отдельной задаче воспроизведения временного опыта используются:

```bash
python -m pip install -r requirements-temporal.txt
python scripts/download_rehab26.py
python scripts/run_temporal_comparison.py
python -m unittest discover -s tests -v
```

Каждый запуск создаёт новый архив и сохраняет исходники/настройки/предсказания; прежние результаты и основная модель не подменяются. Синхронные внутренние проверки выполняются четырьмя процессами с одним CPU-потоком; `--inner-workers 1` включает последовательное исполнение. Проверка архива без обучения: `python scripts/experiment_log.py verify experiments/runs/<имя>`.

Историческая задача [EC3D](reports/ec3d_baseline/README.md) имеет другие классы и формат `(кадры,25,3)`; её модели и показатели не смешиваются с REHAB26.
