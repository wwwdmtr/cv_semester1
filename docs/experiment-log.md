# Как сохраняем историю экспериментов

Цель журнала — иметь проверяемые данные для будущих таблиц, графиков и разбора ошибок. Техническое ведение журнала выполняет ассистент; пользователю достаточно [общей страницы](../experiments/README.md).

## Что уже сохранено

Отдельно архивированы исходный EC3D и первый REHAB26. Копии включают отчёты, настройки, ответы по отдельным примерам, внутренние проверки, графики и все сохранённые модели. Первоначальные рабочие папки остались на месте. Контрольный повтор журналирования подписывается как повтор инфраструктуры, а не как дополнительная независимая выборка или улучшение модели.

У EC3D в самом первом запуске точная версия кода не записывалась, а модели были сохранены позднее повторным обучением. Журнал честно указывает эти ограничения. У исходного REHAB26 проверено совпадение снимка трёх основных скриптов с их хешами, записанными во время обучения. Импорт старых файлов не выдаётся за запись, сделанную до первоначального опыта.

## Как выглядит каждый новый запуск

`experiments/runs/<уникальное-имя>/` содержит:

- `run.json` — что хотели проверить, примечание, исходный запуск для сравнения, статус и сводные показатели;
- `source/` — снимок скриптов, тестов, зависимостей и протокола **до выполнения**;
- `environment.json` — версии Python и используемых библиотек;
- `run.log` — сообщения выполнения и ошибки;
- `reports/` — параметры, хеши данных, разбиения, внутренний подбор, промежуточные результаты внешних разбиений, предсказания, метрики и графики;
- `artifacts.json` — размеры и SHA-256 файлов для проверки неизменности.

Модели хранятся в `models/experiments/<то же имя>/`, путь указан в `run.json`. Это локально сохранённые файлы, исключённые из Git; для переноса на другой компьютер их нужно отдельно скопировать или воспроизвести обучение. Сырые данные в архив опыта не дублируются; источник и хеши сохраняются.

Состояния различаются: `prepared` — только подготовка, `completed` — выполненный запуск, `failed` — ошибка, `interrupted` — обработанное прерывание, `imported_completed` — импорт прежних результатов. После жёсткого завершения процесса без обработки запуска он может остаться `running`; частичные файлы при этом остаются для разбора. Отсутствующие метрики не заменяются нулями.

После завершения исходные файлы запуска не редактируем. Новые выводы можно записывать отдельными заметками, ссылаясь на запуск; исправление кода/данных оформляем новым запуском и объясняем причину.

## Автоматический запуск

```bash
python scripts/rehab26_baseline.py \
  --label baseline_repeat \
  --hypothesis "Проверить воспроизводимость исходного результата" \
  --note "Повтор с прежними данными и признаками"
```

По умолчанию создаются новые уникальные папки отчётов и моделей. Непустые папки, явно переданные через `--output` или `--models-dir`, отвергаются; прежние результаты не затираются. Упоминать исходный запуск можно аргументом `--parent-run <имя>`. Отчёт и графики REHAB26 формируются внутри запуска автоматически, до закрытия архива. Команда `--prepare-only` сохраняет подготовку без обучения и не получает итоговую оценку модели.

EC3D тоже подключён к журналу: `python scripts/ec3d_baseline.py`. Для будущих нейросетевых опытов дополнительно подключим запись loss и метрик по эпохам; в нынешних классических baseline таких кривых ещё нет.

## Как используем результаты в статье

Общая [таблица comparison.csv](../experiments/comparison.csv) содержит все методы каждого опыта, датасет, задачу, статус и способы усреднения. Она позволяет собрать таблицу сравнения и проследить неудачные варианты. Разбиения и предсказания позволяют позже пересчитать нужную метрику, выделить ошибки конкретного человека/ракурса и построить матрицу ошибок без переобучения.

Сравнение улучшения допустимо при согласованных данных, категориях, разбиениях и правилах выбора модели. EC3D с пятью категориями и REHAB26 с тремя не складываются в одну последовательность «стало лучше». Повтор с тем же seed не становится новым независимым человеком или доказательством статистической значимости. Не выбираем удачные тестовые результаты вместо заранее заданной процедуры.

Проверка сохранности:

```bash
python scripts/experiment_log.py verify experiments/runs/<имя>
```

Если производную общую таблицу нужно восстановить: `python scripts/experiment_log.py index`. Сам журнал локальный; внешние сервисы и отправка данных не используются.

## Оптимизация размера будущих запусков — 06.11.2026

Ранее каждый каталог запуска содержал полную копию одинаковых скриптов, тестов, зависимостей и протокола. Это давало линейный рост рабочей копии репозитория. Рекурсивного копирования папки `experiments/` не было, поэтому экспоненциального роста не происходило, но повторение исходников всё равно было лишним.

Начиная со следующих запусков снимок исходников сохраняется один раз в `experiments/sources/<SHA-256>/`. В `run.json` каждого запуска записываются идентификатор снимка и ссылка на общий каталог. Если код не изменился, новый запуск использует уже существующий снимок; если хотя бы один файл изменился, создаётся новый снимок. Старые каталоги запусков не удаляются и не переписываются.

Уникальные результаты разных обучений по-прежнему сохраняются отдельно: метрики, предсказания и внутренний подбор могут отличаться даже при одинаковом коде. Поэтому объём результатов растёт линейно с числом реальных экспериментов. Git дополнительно хранит одинаковые файлы как один объект, но в распакованной рабочей копии общие снимки исходников теперь тоже не дублируются.
