# Пилот переноса нескольких ракурсов в одну камеру — 13.11.2026

Статус: протокол записан до первого обучения этого пилота. Это локальная предварительная фиксация, не внешняя пререгистрация. Данные пяти людей и прежние внешние результаты уже просмотрены; новая вложенная проверка остаётся исследовательской. После запуска этот файл не исправляется ради улучшения результата: изменения гипотезы оформляются следующей версией и новым опытом.

## Вопрос и область вывода

Можно ли при обучении использовать синхронные камеры, чтобы улучшить классификатор, получающий при применении только одну позу одного повтора? Помогает ли перенос с весами для конкретного класса и диапазона ракурса по сравнению с одинаковым переносом всех ответов?

Рабочая гипотеза H1: ограничение переноса по оценённой на обучающих людях различимости класса и ракурса уменьшает ложные замечания относительно обычного переноса, сохраняя обнаружение ошибок. Таблица различимости — инженерный proxy, не физический эталон наблюдаемости. Согласие камер и уверенность не считаются доказательством правильности.

Пилот проверяет только прежние 35 глобальных геометрических признаков MediaPipe world-поз. Он не проверяет полный RGB-путь, временную сеть, неизвестные диапазоны ракурсов или независимый набор. Отрицательный результат не опровергает весь перенос знаний. Положительный не доказывает научную новизну или универсальную наблюдаемость дефекта.

## Данные и доступная информация

- Проверенный поднабор REHAB26: 388 физических повторений, 5 людей, 3 синхронные камеры, 1 164 наблюдения; прежние три категории и прежние фильтры.
- Все камеры одного повтора имеют общую метку и всегда остаются у одного человека в одном разбиении.
- При обучении доступны метки, синхронные виды и относительный угол камеры из разметки. ID камеры не заменяет относительный угол.
- При проверке student получает только 35 признаков одной камеры. Другие камеры, истинная метка, угол, личные эталоны и имя человека ему не передаются. Каждая камера оценивается отдельно; это проверка разных однокамерных входов, не трёхкамерное применение.
- Покрытие 100%, отказов и настройки порога на внешних данных нет.

## Учитель, мягкие цели и пять условий

Teacher: логистическая регрессия с `C=1`, балансировкой по истинным классам и теми же 35 признаками. Настройки фиксированы. Для каждого target-человека teacher обучается только на остальных людях текущего обучающего поднабора. Его три вектора `predict_proba` одного физического повтора усредняются: `t`. Это не точная вероятность правильности.

Student: та же логистическая регрессия; во всех условиях одинаковый внутренний выбор `C ∈ {0.1, 1, 10}`, `balanced ∈ {False, True}`. Сила переноса `alpha=0.5` фиксирована во всех условиях и не выбирается по результату. `y` ниже — one-hot истинная метка.

| Условие | Цель обучения |
|---|---|
| `supervised` | `q = y` |
| `label_smoothing` | `q = (1-alpha)*y + alpha*(1/3,1/3,1/3)` |
| `distill_uniform` | `q = (1-alpha)*y + alpha*t` |
| `distill_global_gate` | `q = (1-alpha*gbar)*y + alpha*gbar*t` |
| `distill_class_view_gate` | `q_c = (1-alpha*g_c)*y_c + alpha*g_c*t_c`, затем нормировка суммы до 1 |

`label_smoothing` проверяет пользу простого сглаживания меток при том же коэффициенте смешивания; энтропия его целей не обязана совпадать с teacher. `distill_global_gate` проверяет общее ослабление переноса, но не является точным matched-strength контролем после поклассовой нормировки. Даже преимущество над этими контролями не заменяет последующие абляции.

Таблица `g` строится только по single-view cross-fit ответам teacher внутри текущего student_train. Диапазоны фактического `abs(view_angle)`: `<=30`, `30<angle<60`, `>=60` градусов. Для каждого дефекта `c∈{1,2}` и диапазона считаются one-vs-rest TPR и TNR с Beta(1,1)-сглаживанием: `(TP+1)/(P+2)` и `(TN+1)/(N+2)`. `g_c = max(0, TPR+TNR-1)`. При отсутствии положительных ИЛИ отрицательных примеров в ячейке `g_c=0`: псевдосчётчики не доказывают различимость отсутствовавшего класса. Для корректного класса `g_0 = min(g_1,g_2)`, поскольку отсутствие двух ошибок требует обеих оценок. Таблица сохраняет реальные числа наблюдений, уникальных физических повторов и их веса. `gbar` — среднее всех трёх компонентов gate по обучающим наблюдениям с весами физических повторов.

На конкретном примере gate не выбирается по его истинной метке и не обнуляется правилом «teacher ошибся». Метки используются для обучения общей таблицы различимости. Внешние метки в ней не участвуют. `g=0` возвращает supervised, `g=1` — обычный перенос. Поклассовая нормировка может менять относительные массы классов; это часть фиксированного метода, а не выпуклая смесь с одним коэффициентом.

Мягкие цели реализуются взвешенной cross-entropy через размножение строки на классы. Скалер обучается на исходных строках и физических весах, а не на размноженной таблице. Веса классов рассчитываются по hard labels текущего train и применяются одинаково. Суммарный базовый вес трёх камер физического повтора равен 1. При балансировке суммарная масса loss после class weights может различаться между условиями: используется class-weighted soft cross-entropy, а не гарантия одинаковой эффективной регуляризации.

## Вложенность и защита от подсматривания

1. Outer leave-one-person-out: 4 человека train, 1 test.
2. Внутри outer_train — leave-one-person-out для выбора student-параметров: 3 человека train, 1 validation.
3. Для КАЖДОГО inner_train учитель и таблица строятся заново cross-fit по этим трём: teacher обучается на 2, предсказывает все виды третьего. Ни inner_validation, ни outer_test не участвуют.
4. После внутреннего выбора цели outer_train создаются cross-fit `3→1` внутри четырёх; student обучается на четырёх и проверяется на внешнем человеке.
5. Кэш разрешён только по точному набору train ID и фиксированным настройкам учителя. Исторические внешние предсказания не используются для обучения новых целей.
6. Выбор student: сначала выполнение прежних ориентиров `FPR<=20%`, `recall>=80%`; затем максимальный средний по внутренним людям Macro-F1, меньший FPR, больший recall, стабильный ID. Внешние результаты не выбирают метод или его параметры.

## Показатели и заранее заданная интерпретация

Главные показатели усредняются по пяти людям: Macro-F1 трёх классов, FPR на корректных повторах, обнаружение любой ошибки и правильного типа ошибки. Сохраняются каждый человек, каждый класс, camera ID и фактический диапазон ракурса. Камеры/повторы не объявляются независимыми людьми. Pooled-показатели, если есть, подписываются отдельно.

Практический критерий H1, выбранный до запуска: conditional относительно `distill_uniform` снижает средний FPR минимум на 3 процентных пункта, теряя не более 2 п.п. обнаружения ошибок; Macro-F1 не уменьшается; FPR уменьшается хотя бы у 3 из 5 людей. Эти границы — решение данного пилота, не статистический или медицинский норматив.

Проверка полезности для проекта отдельно: условный перенос также должен улучшать прежнее supervised-условие; выигрыш только над неудачным обычным переносом не означает улучшение проекта. Если условие не превосходит `distill_global_gate`, отдельно выделить объяснение меньшей силой переноса. Если не превосходит `label_smoothing`, не приписывать выигрыш именно многоракурсным знаниям. При mixed trade-off показать все показатели и не объявлять победу по одному числу.

Диагностика самого cross-fit teacher: качество одного вида и среднего трёх на тех же внутренних людях. Слабый teacher — возможная причина неудачи. Сравнение с историческим Macro-F1 0.672 служит проверкой воспроизведения, а не подбором настроек.

## Артефакты и следующие проверки

Новый запуск через `Experiment`: исходники до запуска, версии библиотек, копия этого протокола, хеши данных/признаков, manifest и splits, все внутренние выборы, таблицы gates/counts, teacher train/target people, внешние ответы, метрики и 25 моделей разбиений с проверкой загрузки. Финальная модель на всех данных на этом этапе не создаётся. Успешные и неудачные опыты сохраняются. Дневник: [research-diary.md](research-diary.md).

При положительном пилоте: независимые люди/сессии, второе упражнение с согласованными критериями, сравнение с ближайшими методами и проверка углов без готовой разметки. При отрицательном: отделить слабого учителя, ограниченное представление student и неудачный proxy gate; новый вариант фиксировать до нового запуска. Результаты одних пяти людей после повторного использования остаются exploratory.

Близкие работы: [REHAB26](https://arxiv.org/abs/2609.35726v2), [ViCoKD](https://arxiv.org/abs/2511.12870), [PhaseAware](https://arxiv.org/abs/2607.20237). Сам перенос, фазы, ракурс и отказ не заявляются новой идеей. Возможный вклад — проверяемая закономерность и границы переноса для конкретных дефектов; наличие такого вклада ещё не установлено.
